# 第一天上手教程

从零开始，30 分钟内让第一条真实行情和第一笔可执行机会出现在终端里。本教程对应
`forever` 分支：**魔兽世界：无限（WoW Forever）客户端 1.60.1**。TBC 周年服 2.5.6
的步骤在 `anniversary` 分支。

## 前置条件

- Windows + 魔兽世界：无限客户端（1.60.1，Interface 16001）
- Node.js 20+

## 第 1 步：启动终端（约 5 分钟）

```powershell
cd <项目目录>
Copy-Item .env.example .env
npm install
npm run db:push
npm run items:catalog:import   # 物品静态事实（名字、品质、卖价、图标 id）
npm run icons:fetch            # 下载共享图标到 public/icons（已被 gitignore）
npm run recipes:import
npm run dev
```

打开 `http://localhost:3000`。此时市场是空的——真实数据在第 4 步接入后出现。制造页
会显示 2,595 条 Forever 配方（1,147 条 1.60 新增），但还没有价格，所以没有正利润
的制造机会。

## 第 2 步：安装游戏内插件（约 2 分钟）

把 `addon\WoWDerhoiAH` 整个文件夹复制到客户端实际使用的数据目录下的插件目录：

```text
<游戏数据目录>\Interface\AddOns\WoWDerhoiAH
```

`<游戏数据目录>` 以启动器实际使用的那一层为准。复制后目录里应直接可见
`WoWDerhoiAH.toc`（不能多套一层文件夹）。如果游戏已经开着，需要重新登录角色
（或 `/reload`）才会加载插件。

## 第 3 步：第一次扫描与诊断（约 3–5 分钟）

1. 进游戏，走到拍卖师面前打开拍卖行。
2. 聊天框输入 `/wahdiag`。这是开服排雷：它会打印时间左返回值的类型、owner 可见率、
   `SaveAddOns`、上架 API、押金、在售、节流、Journal/账本、阶段、邮箱和制造采集。
   把异常项记下来；只关心邮箱时用 `/wahdiag mail`。
3. 输入 `/wahscan`。插件调用 `C_AuctionHouse.ReplicateItems()` 一次复制整个拍卖行；
   聊天框显示 `已接收 N 条拍卖，处理中...`，随后是 `扫描完成`。
4. 如果服务器已经开了一段时间，用 `/wahopen -<小时数>`（或 `/wahopen now`）设开服
   锚点，阶段才不会按本机首次扫描从点火期重来。
5. **小退到角色选择界面或 `/reload`** —— 即使插件会在扫描后尝试 `SaveAddOns`，
   第一次也先确认文件真的落盘。

AH 开着时可以 `/wahauto` 开启自动重扫（间隔来自编译规则，默认 15 分钟）；玩家主动搜索时
自动扫描会暂停。请求失败后插件给出重试窗口，不会把已收到的数据按墙钟中止。

## 第 4 步：接通数据管道（约 3 分钟）

找到 SavedVariables 文件，路径形如：

```text
<游戏数据目录>\WTF\Account\<你的账号ID>\SavedVariables\WoWderhoiAH.lua
```

写进 `.env`：

```ini
AQT_SAVEDVARS_PATH="<游戏数据目录>\\WTF\\Account\\<你的账号ID>\\SavedVariables\\WoWderhoiAH.lua"
```

保持 `npm run dev` 运行即可：应用会自己监听 `AQT_SAVEDVARS_PATH` 指向的存档。
日志出现 `Imported N items, M positions and K trades from scan ...` 就说明盘口、
序列和 Journal 都已入库。刷新 `http://localhost:3000`。

## 第 5 步：在游戏里用起来

- 打开拍卖行：WAH 驾驶舱默认在右侧自动打开（`/wahtrade` 手动开关）。
- **驾驶舱**：状态行显示扫描龄、在售种类、阶段和卖家可见率；雷达列出可买数量、
  买价、建议卖价、净利和成交率，NPC 必赚排最前。
- **购买**：物品拍卖点“购买”会先重读实时一口价，变价则中止；商品点“购买*”按数量
  走客户端自己的确认框。确认后这次购买会写入 Journal，下次扫描时账本里能看到头寸。
- **卖出**：`/wahsell` 或驾驶舱的“卖出”按钮。选背包物品，看建议卖价、挂单价、
  12/24/48 小时押金、售出净利和两种保本价；点“压价上架”走客户端上架流程。
- **卖价指引**：把要卖的物品拿在鼠标上，输入 `/wahprice`；或在命令后跟物品链接。
- **成交回执**：每次打开邮箱，插件读取成交发票，把成交写成“确认成交”（不是推断），
  并带上挂单时间；同一封邮件重复开箱不会重复记账。卖出后记得开一次邮箱。
- **制造**：制造完成的物品会按材料账面成本入账；材料本身没记过买入时，账本会标
  “短头寸”，表示成本未知，而不是凭空记零成本。
- **提示框**：背包、银行、装备、商人、拍卖行和聊天物品链接都会带价格块；法术、
  单位、宠物等非物品链接不带。建议卖价领衔，随后盘口、供给、推断成交和 P10（统计）；
  趋势相对建议卖价中位，并写明窗口。提示框只读，不挂任何按钮。
- **图表**：默认盘口阶梯；有两个以上扫描点后可切走势，支持 1h/6h/24h/7d/全部。
  图表是拍卖行或 WAH 驾驶舱旁的面板，随面板常驻，所以盘口/走势和窗口按钮随时可点；
  悬停物品只决定图表显示哪个物品，不会把图表拖到鼠标旁边。走势窗口读取完整保留的
  序列，不会被阶段默认窗口截断；终端走势还会用更早日线收盘补足 48 次快照之外的日子。

## 第 6 步：看终端

- 驾驶舱：阶段横幅、账本摘要、行动清单、可执行机会、市场变动与数据就绪；完整行情在 `/market`。
- 商品页：盘口阶梯、24 小时成交概率、走势、日线 K 线。
- 组合页：现金（上次扫描）、持仓市值/成本、浮动、确认成交的已实现；推断成交单列，
  不计入已实现与校准。
- 制造页：按影子价格排序的制造计划；约束是每专业每日次数、材料在售量和预算。
- 复盘页：决策匹配、alpha 衰减、下一次实验设计。

## 日常循环

每天只需要：开拍卖行 → `/wahscan`。插件在扫描结束后调用 `SaveAddOns`，
应用会发现新文件并入库；若客户端不支持即时落盘，再小退或 `/reload`。
同一次扫描不会重复导入。序列积累两天以上后，
走势与星期季节性开始有意义；积累自己的成交后，成交率区间才会收窄。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 插件列表里没有 WoWDerhoiAH | `.toc` 不在文件夹第一层，或客户端版本不是 1.60.1（`## Interface: 16001`） |
| `/wahscan` 提示先开拍卖行 | 必须站在拍卖师面前且拍卖行窗口开着 |
| 扫描无应答 | 180 秒内客户端没有交付复制数据；确认 AH 已打开，等聊天框给出的重试秒数后再试。处理已收到的数据不设时限 |
| watcher 报 `AQT_SAVEDVARS_PATH is not set` | `.env` 里没配路径，或路径带引号错误 |
| watcher 一直没反应 | 先看 `/wahdiag` 的 `SaveAddOns` 与数据龄；客户端不支持即时落盘时，小退或 `/reload` 一次 |
| 导入报 409 | 同一次扫描已导入过且没有附带 Journal；邮箱成交后的账本重放会返回 200，不报 409 |
| 导入报 400 | 扫描不是 v4；用当前插件重扫 |
| 配方页为空 | 运行 `npm run recipes:import` |
| 卖出页提示被客户端拦截 | taint 限制；按聊天框给出的价格手动上架，账本不会记录 |
| 商品点购买后还要确认 | 正常：商品按市价成交，最终总价由客户端确认框显示 |
